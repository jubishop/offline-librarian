## Findings

### F1: Threads that log at once can both move the log aside  (fixed)

- **severity:** Warning
- **status:** fixed
- **location:** librarian/agent.py:44
- **scope:** in-diff
- **concern:** `update run` passes `job_log` to `kiwix.fetch`, whose download threads log concurrently, and an unlocked `bound_logs` let two of them rotate one full log: the second could move the fresh log over the previous one, losing it, or raise `FileNotFoundError` from `log()`, which `fetch` reports as a failed download
- **resolution:** `bound_logs` now holds a module lock, so a second thread sees the fresh log and leaves it; `test_threads_that_log_at_once_move_the_full_log_aside_once` covers it
- **fixed_at:** 2026-11-02

### F2: Build processes keep writing to a log that moved aside  (skipped)

- **severity:** Nit
- **status:** skipped
- **location:** librarian/build.py:64
- **scope:** related
- **concern:** a `multiprocessing.Pool` started before the update rotates its error log keeps the old descriptor, so a child's stray stderr output lands in `.previous.log`, or in a deleted file after a second rotation
- **resolution:** the parent logs every problem the children report, a child's exception is raised in the parent, and each pool lasts one source's build, so at most a few stray warnings are misplaced

### F3: The thread test hangs the run if bound_logs regresses  (fixed)

- **severity:** Nit
- **status:** fixed
- **location:** tests/test_agent.py:102
- **scope:** in-diff
- **concern:** the helper thread waits without a timeout for a log to move aside, so a regression where none moves leaves a non-daemon thread that keeps `bin/check` from exiting, or runs CI to its 10-minute limit
- **resolution:** the helper thread is a daemon, so the test fails and the run exits
- **fixed_at:** 2026-11-02
